# PokéBonk：ゲームバランス解析・独立シミュレーター計画

更新日: 2026-10-20
場所: `PCSKTestBox/rea` の実験用ブランチ
優先端末: PCブラウザー（スマホ表示は後日対応してもよい）
状態: **設計のみ。ゲーム内数値・公式アルゴリズムの実測やコピーは未実施。**

## 目的

1. 公開ゲームの通常プレイを観察し、敵AI、戦闘、経験値、スキル、進化、敵スポーン、アイテム、難易度の仕組みを説明する。
2. クライアントから観測できた値と、推定しかできない値を必ず区別する。
3. 独自実装のパラメータ駆動型ゲーム実験室を作り、値を変えて難易度・勝率・生存時間などを比較する。
4. Windows/Macの個別設定を必須にしない。CLI解析と独自シミュレーターの自動テストはGitHub-hosted UbuntuのActionsで実施する。
5. ゲーム本体の改造、チート、実ゲームの自動操作、サーバー通信の操作を行わない。

## 調査項目・評価指標

| 領域 | 調べる構造 | 実験室での評価指標 |
| --- | --- | --- |
| 敵AI | 索敵条件・距離・追跡・攻撃遷移・障害物回避 | 接敵時間、被弾回数、到達率、行動状態の滞在比 |
| 戦闘 | HP/防御/倍率/攻撃周期/射程/当たり判定/範囲 | DPS、TTK、被ダメージ/分、集団処理時間 |
| レベル | XP付与/必要XP曲線/選択候補/能力強化 | レベル別必要XP、到達時間、アップグレード頻度 |
| 敵出現 | 数・場所・頻度・時間/フェーズ補正 | 敵密度、脅威量/分、フェーズ別ピーク |
| キャラ性能 | 初期能力、技、移動能力、役割 | 同条件の生存時間・処理量・戦闘安定性 |
| スキル・進化 | 組合せ/条件/強化幅/上限 | 相乗効果、強化前後の性能、偏り |
| 難易度・報酬 | 成長速度と敵強化速度の関係 | 勝率、失敗地点、受領報酬/時間 |

* DPS＝単位時間あたり平均ダメージ。TTK＝敵を倒すまでの時間。
* **サイトから確認されていない具体的な数値は埋めない。** すべての変数に `observed` / `source-backed` / `hypothesis` / `synthetic` を付与。

## 観測と検証のフロー

### Stage A — 根拠の取得
- REA CDPによるページ構造・読み込みスクリプト一覧・初期動作の受動的観測。
- JavaScriptソースの静的依存関係整理（保存先は権限制限した領域）。
- バージョン・実行日時・観測条件・証拠IDを記録。更新により情報が変わり得る。
- 公開されている第三者ガイドは候補資料としてのみ扱い、公式ゲームの最新版の確定事実と混同しない。

### Stage B — ゲーム仕組みのモデル化
- `state_machine`: 待機→追跡→射程内攻撃→クールダウン等の**仮説**を作り、根拠ごとに分離。
- `combat`: 攻撃周期・ダメージ式・対象数・回避確率の依存関係を整理。
- `progression`: 必要XP曲線・ラン内強化・恒久強化を分ける。
- `waves`: 時間/段階ごとの出現規則を整理。

### Stage C — 独立した調整可能シミュレーター
- 実ゲーム由来のコード・画像・データをそのまま再配布しない。
- 敵速度、索敵距離、攻撃間隔、HP、XP係数、敵出現率、スキル係数、成長倍率をJSON設定で変更可能にする。
- A/B比較は乱数シード、開始条件、プレイ方針を固定。
- 複数シードの統計を表示し、平均だけでなく中央値・分散・パーセンタイルも見る。
- プレイヤー代替の独自シミュレーションAIを使う場合は、それが**元ゲームのAIではない**と明記。リアルゲームには接続・投入しない。

### Stage D — 自動テストと可視化
- 設定値変更 → 独立シミュレーター実行 → 指標比較 → HTMLレポート生成。
- GitHub Actionsで人手のRun workflowまたは安全な変更検証を実行。
- 公開リポジトリのActionsログやArtifactsに実サイトの生ソース・セッション・クッキー・非公開情報を保存しない。
- 可視化はPCを優先したブラウザーページ。レスポンシブ設計でスマホ閲覧も可能にする。

## 最初の比較シナリオ案（値は**仮**）

1. 敵の追跡速度を基準比 +20% → 接敵時間、生存時間の差。
2. 敵出現間隔を -15% → 敵密度、処理しきれない時刻の差。
3. XP必要量を +25% → レベル到達時刻、火力差。
4. スキル威力を +10% → TTK、生存率の差。
5. 敵HPがフェーズごとに増加 → パワースパイク発生時刻の差。

これらはゲームの実際の値・ルールの主張ではない。実測根拠が揃った段階で置き換える。

## 完成条件

- ゲームシステム分析表に根拠と不確かさが付いている。
- 敵AI・経験値・戦闘・難易度について独立した操作可能なモデルがある。
- 1要素だけ変える比較を同じ条件で再現できる。
- PCからGitHub Actionsを実行し、結果を確認できる。
- スマホ対応は第二段階とし、初期実装の妨げにしない。
