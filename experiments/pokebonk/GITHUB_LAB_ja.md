# PokéBonk調査用 GitHub Actions — 使い方

このページはGitHub-hosted Ubuntuランナーで実行する **PokéBonkの受動的観測＋独立ゲームバランスの仮モデル** の説明です。

## すべてPC不要で実行する

GitHubの「Actions」から **PokéBonk research: REA signals + balance lab** を開き、**Run workflow** を押します。通常はブランチ `main` を選びます。

入力欄（数値は**PokéBonkの実際の設定値ではありません**）：

| 入力 | 何を変更するか | 既定値 |
| --- | --- | ---: |
| enemy_speed | 独立シミュレーターでの敵速度倍率 | 1.20 |
| spawn_frequency | 独立シミュレーターでの敵出現倍率 | 1.15 |
| xp_cost | 独立シミュレーターでの必要XP倍率 | 1.25 |
| trials | 同じ乱数シードで比較する試行回数 | 40 |

範囲は各倍率0.5〜2、試行回数5〜200です。数値を変えずに最初のテストを実行してください。

## 結果を見る

- GitHub Actionsの実行履歴をクリックし、ジョブの**Summary**を開きます。
- 「ゲームバランス仮モデルのA/B比較」：生存時間・撃破数・到達レベルなど。**独自実装の仮定だけによる比較であり、PokéBonkの実測結果ではありません。**
- 「REA JavaScript検出シグナル」：公開クライアントから取得できたJavaScriptを、用語グループごとの**出現回数だけ**で整理したものです。用語の出現は本物の敵AI・計算式を証明しません。
- Artifactsから `pokebonk-aggregate-and-synthetic-only` を選ぶと、同じ安全な集計JSONをダウンロードできます（7日で消去）。ゲームのコード・URL・個別ファイル名・プレイ情報は含まれません。

## 注意事項

GitHubのPublicリポジトリなので、公開ログやArtifactsにゲーム本体のJavaScript・アセット・機密情報を出しません。REAが取得した生データは一時ランナーの中だけに保存し、ジョブ終了時に破棄します。今後実際のAIや経験値の計算式を厳密に確定するには、権利・プライバシーに配慮した非公開環境でコード内容の検証と、許可された通常プレイの観測が別途必要です。

本物のゲームでチートや自動プレイを行うものではありません。元ゲームは変更せず、独立シミュレーターのパラメータだけを変更します。
